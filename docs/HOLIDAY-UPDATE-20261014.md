# 节假日库接入与年度维护契约

文档版：`agenda-holiday-library-20261014-v2`；2026-10-14。目标：DSH Desktop `0.2.0-rc.2`。用户明确要求实施完整 0.4.0 方案，确认本版具体契约；已实现，验收见 [0.4.0 验收](VERIFICATION-0.4.0.md)。

本契约替代 `agenda-holiday-update-20261014-v1` 的常驻联网任务方案，承接 [SPEC F005、F008、F010](SPEC.md)，与 [Desktop 适配契约](DSH-UPGRADE-20261011.md) 一起实施。此前“可以”确认的是上一轮建议中的 npm 库方向，不倒推为对随后生成的全部迁移／接口细节的确认；原始需求只读保留。

## 1. 数据源与年度维护

- 采用 Node.js 包 `chinese-days` 的本地年度数据，计划初始精确版本为 `1.5.9`，在依赖与锁文件中固定。已只读核对该 npm 发布包具有 CommonJS／ESM 产物、TypeScript 声明和 2004–2026 年年度 JSON。
- 日常查询完全离线。上游收录新年度后，在维护会话中更新精确 npm 依赖、验收节假日样本、构建并发布 Agenda 新版；用户升级插件获得新数据。没有新版年度数据时，更新包管理器本身不能产生新安排。
- 不新增公告抓取器、年度更新定时器、模型任务、Python 环境或“立即联网更新”按钮。原提案的 holidayAutoUpdate、检查周期、重试、候选应用与更新状态存储全部退出当前设计；这些字段／操作从未实现或写入本次运行环境，不创建相应迁移任务。
- 包内 holidays/2025.yaml、holidays/2026.yaml 保留为固定的旧默认值比较基线；今后不再按新公告改写这些比较基线，也不继续 seed 默认数据到用户目录。默认数据来源统一为 npm 库。
- chinese-days 的农历／节气能力不属于本次接入范围。Agenda 现有农历算法、事件和重复待办语义保持。

## 2. 宿主适配

- 增加宿主数据适配层，从已安装 chinese-days 包的公开年度 JSON 转换为现有 `HolidayYear { year, holidays, workdays }`。解析限定合法年度文件名；不依赖维护者源码目录、GitHub/CDN 或当前工作目录。
- 使用年度 JSON 的 holidays 与 workdays；inLieuDays 不另算一组放假，避免同一天重复统计。名称由适配层统一投影为现有中文文案（包括清明节、端午节、中秋节），不把上游逗号编码直接交给界面。
- 可用年份来自实际安装包的年度文件，不把最高年份后按周末推算的数据称为官方安排。每项日期、所属年份、重复／冲突及数据结构在适配层校验；未来库升级导致格式不兼容时明确失败并保留本地原件。
- 库数据只由宿主读取并缓存；浏览器只接收 Agenda 的 JSON 投影，不引入 Node 模块或复制第二套日历判断。
- HolidayService.loadYear／availableYears 提供库默认值与本地覆盖后的有效资料；既有存储读写接口仍表示本地资料。UI、模型工具和统计查询继续经同一 AgendaService。

## 3. 旧 YAML 与本地覆盖

- 保留用户目录 holidays/<year>.yaml 的原始字节，包括注释和未知字段；首次接入采用读取时归并，不自动改写、删除、搬迁或重新 seed 原件。
- 对有固定旧默认值基线的 2025／2026 年，按日期规范化比较本地资料与旧基线。完全相同的日期继承库默认值；新增或修改的放假／上班记录作为本地覆盖；删除旧基线中某日期的标记表示恢复该日普通周末／工作日判断，不能让库把该标记自动加回来。
- 日期比较使用标准中文名称与确定性排序，不把 YAML 顺序、格式或注释变化当作业务修改；原始文件始终保留。不存在本地文件时直接使用库默认值。
- 对没有旧默认值基线的年度，无法可靠区分默认资料与手改，保留整年本地覆盖语义并在设置页标明“本地年度资料”；该年不会因 npm 更新被静默替换。
- 最终优先级：本地明确覆盖 → 库放假／调休资料 → 普通周末／工作日。整年本地覆盖的年份使用原有整年语义；库尚未收录但本地年度文件有效时仍可使用本地资料。
- 本地资料非法时保留原件并显示具体问题，不静默当作合法覆盖。已有效读取的缓存可继续使用；首次读取失败而库有资料时使用库默认并明确提示本地文件未应用。
- 年度文件变更或插件重载后，重新归并并失效对应年缓存。发现有效结果变化时通知所有页面；事件／待办 CSV、类别及 weekStart 设置不因本次接入而重写。
- 遗留配置核对包括运行配置和完整引用；真实环境若发现与已撤回设计同名的未知字段，先查来源，不因本次草案删除而擅自删除用户配置。

## 4. 界面与接口

- 在 Agenda 设置卡展示库版本、已收录年份、本地覆盖年份及资料问题。未收录年份显示“该年放假安排未载入”；仍可显示普通周末，但不预测法定放假或调休。
- AgendaSnapshot 追加只读 holidayData 摘要：packageVersion、supportedYears、localOverrideYears、legacyFullYears、warnings。摘要只含版本／年份和简短问题，不发送原始路径或完整本地文件。
- 原 13 个 agenda_* 工具、HolidayYear 与日期分类类型保持；不新增联网／更新工具或 WS 更新操作。包更新通过插件维护流程完成，界面不自行执行 npm install。
- weekStart 沿用 Desktop 适配方案中的设置保存／修订保护，不新增节假日自动更新开关。

## 5. 验收与交付边界

- 默认资料：普通工作日／周末、2026 元旦放假、1 月 4 日调休上班、2 月 14 日调休、春节与国庆；工作日优先级和中文名称与现有预期一致。
- 数据范围：实际年度文件识别、未收录年份提示、本地独立年度、非法／冲突年度数据、宿主包资源路径和纯客户端 bundle。
- 旧数据：旧 seed 完全相同不遮挡库新默认；单日新增／改名／删除分别形成覆盖；未知字段／注释原件保留；无比较基线保持整年本地语义；npm 数据更新只改变未覆盖日期。
- 升级与页面：更换精确依赖版本后实际读取新包数据，所有页面共享同一结果，重启与本地年度资料改动后缓存正确；断网仍可完整使用已安装资料。
- 开发后执行 typecheck、test、build 与隔离 Desktop 页面／安装验收，分开记录。纯文档本轮不安装依赖、不修改源码／测试实现／运行配置、不运行产品构建或填写兼容通过。
