# agenda — 个人日程管理

`agenda` 是 `dsh-agenda` 插件的自然语言层：你（Agent）把用户的中文表达翻译成下面 13 个确定性的
工具调用。所有修改都会保存到用户本地的 `<DSH_DATA_DIR>/agenda/`（CSV + YAML），
与 UI 页面共享同一份数据。

## 何时使用

- 用户要**查看**日程 / 待办：今天、明天、本周、本月、某天的安排；
- 用户要**创建**日程（公历或农历）或待办；
- 用户要**修改 / 移动 / 删除**日程或待办；
- 用户要**完成 / 重新打开**待办；
- 用户要**统计**（本周 / 本月 / 自定义范围）或**搜索**日程 / 待办。

## 工具清单（13 个，全部是明确的小工具）

| 工具 | 作用 | 典型自然语言 |
| --- | --- | --- |
| `agenda_create_event` | 新建日程（公历 / 农历，全天 / 定时） | “明天下午三点安排算法评审” “添加农历八月十五全家聚餐” |
| `agenda_get_event` | 查看单个日程详情 | “看下这个日程的详情” |
| `agenda_update_event` | 修改日程（标题 / 时间 / 分类 / 地点 / 备注） | “把周五下午的会议改到四点” “把会议的标题改成算法评审” |
| `agenda_delete_event` | 删除日程 | “把这个日程删掉” |
| `agenda_list_events` | 列出日程（可按日期范围） | “这个月有什么安排” “下周的日程” “今天还有什么事情” |
| `agenda_search_events` | 搜索日程（标题 / 备注 / 分类） | “查一下这个月和第二技术路线有关的安排” |
| `agenda_create_todo` | 新建待办 | “添加一个待办：整理算法评审材料” |
| `agenda_update_todo` | 修改待办 | “把待办改到明天” |
| `agenda_complete_todo` | 完成待办 | “把这个待办标记完成” |
| `agenda_delete_todo` | 删除待办 | “删掉这条待办” |
| `agenda_list_todos` | 列出待办（日期范围 / 状态过滤） | “今天有什么待办” “这周未完成的待办” |
| `agenda_search_todos` | 搜索待办 | “找一下和评审相关的待办” |
| `agenda_get_statistics` | 范围统计（日程数 / 待办完成 / 分类聚合 / 时间投入） | “这周忙不忙” “统计一下这个月的安排” |

## 自然语言 → 工具映射示例

1. “明天下午三点安排算法评审” → `agenda_create_event(title: "算法评审", start: "<明天> T15:00", end: "<明天> T16:00")`
2. “添加一个全天日程：项目结项” → `agenda_create_event(title: "项目结项", start: "<日期>", all_day: true)`
3. “把周五下午的会议改到四点” → 先 `agenda_list_events(from: <本周五>, to: <本周五>)` 找到目标，
   再 `agenda_update_event(id: <找到的 id>, start: "<本周五>T16:00", end: "<本周五>T17:00")`
4. “今天还有什么事情？” → `agenda_list_events(from: <今天>, to: <今天>)`
5. “这周有什么待办” → `agenda_list_todos(from: <本周一>, to: <本周日>)`
6. “添加一个待办：整理算法评审材料” → `agenda_create_todo(title: "整理算法评审材料", date: <今天>)`
7. “把这个待办标记完成” → `agenda_complete_todo(id: <待办 id>)`
8. “统计一下这个月的安排” → `agenda_get_statistics(from: <本月1号>, to: <本月最后一天>)`

## 日期与时间解析（务必遵守）

- 依赖当前日期（系统时间上下文）解析相对日期：“今天”“明天”“后天”“昨天”“本周一”“下周五”“下个月 3 号”；
- 时间格式统一 `HH:mm`，日期格式 `YYYY-MM-DD`；定时事件传 `YYYY-MM-DDTHH:mm`；
- 只说“下午三点”= 15:00；“上午九点”= 09:00；整点默认 `:00`；
- 未说明结束时间时：全天事件 end 省略（=同日）；定时事件 end 省略（= 开始 +1 小时）；
- 跨天事件：end 传更晚的日期（如 21:00 开始到次日 01:00 结束，end 传次日 `T01:00`）；
- “周末”= 本周六、周日；“工作日”按实际星期判断。

## 农历日程（正式能力，不是展示）

- 用户说“农历八月初五”“八月十五中秋”“闰二月初一”等时，走农历路径：
  `agenda_create_event(title: ..., calendar_type: "lunar", lunar_year: <当前农历年>, lunar_month: <月>, lunar_day: <日>, lunar_leap: <是否闰月>)`；
- 系统会把农历换算为公历并**保留原始农历字段**（不会只存公历日期）；
- 农历事件的时间：默认 09:00–10:00，可传 `start_time` / `end_time`（`HH:mm`）；
- 农历年份取与当前日期最接近的农历年（如今天在 2026-09，农历年为 2026；腊月/正月跨年时以“春节”为界判断）；
- 用户只报“几月几日”没提“农历”时，默认按公历处理。

## 分类（多级路径）

- 分类是路径式、层数不固定：`工作/防干烧/算法`、`生活/家庭`；
- 创建日程 / 待办时 category 传完整路径；新路径会被自动登记到分类表；
- 未说明分类就不填，不要臆造。

## 关键约定

- **删除前必须确认**：删除日程 / 待办属于破坏性操作，若用户表达不够明确（“把那个删了”但指代不清），先列出候选让用户确认；
- 所有结果以工具返回的 `ok` / `message` 为准，不要凭印象复述；
- 一个意图只调一个工具：先查询定位（list / search / get），再执行修改（update / delete）；
- 找不到目标时如实告知，不要编造 id；
- 统计的 from/to 必须都是 `YYYY-MM-DD`（含当天）。
